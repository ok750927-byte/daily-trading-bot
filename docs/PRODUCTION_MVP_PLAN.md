# 5단계: 고도화 / 실전 적용 — MVP 계획

목표: 안정성과 안전장치를 우선으로 하여 실전 계좌 연동이 가능한 최소 실용 제품(MVP)을 빠르게 만들고 단계적으로 확장합니다.

주요 분야
- 전략 다변화 (멀티모델): 딥러닝/강화학습(모듈화된 실험 환경), 앙상블·멀티모델 운영
- 실전 계좌 연동: 브로커 어댑터, 트랜잭션 idempotency, 주문 시뮬레이션(dry-run)과 실제 전환 플래그
- 자금·위험관리: 포지션 사이징, 계좌레벨 제약, 시장·종목별 노출 한도, 일일 손실 제한(ML/heuristic)
- 실시간 운영: 낮은 지연 주문 파이프라인, 모니터/알람, 장애 복구/재시작 정책, 트랜잭션 로그와 재동기화
- 운영 자동화: CI/CD, 카나리 배포, 자동 회귀/회복 테스트, 백fills 및 재처리

단계별 마일스톤 (MVP로 8주 목표)

1) 준비 및 안전장치 (1주)
  - 계약/목표: 실전용 브로커 API 사양 확보(샌드박스 권장)
  - 준비물: 키링/시크릿 관리, 운영자 권한 모델, 감사 로그 디자인
  - 산출물: `src/trading/broker_adapter.py` 인터페이스, `src/trading/risk_manager.py` 스켈레톤

2) 위험관리(초기) + dry-run 주문 파이프라인 (2주)
  - 포지션 사이징, 계좌 노출 체크, 주문 전 위험 체크
  - RealtimeTrader에 dry_run->live 전환 토글 추가(승인 워크플로우 결합)
  - 테스트: 단위 테스트 + 시뮬레이션 시나리오

3) 전략 다변화(파일럿) (2주)
  - 멀티모델 엔트리 포인트: `src/modeling/rl_agent.py`(훈련/평가/배포 인터페이스)
  - 배치 학습 파이프라인과 온라인 평가 루프 분리

4) 운영 및 복구 자동화 (2주)
  - 장애 복구: 주문-재시도/재동기화, 미체결 주문 재검증(OrderManager 보강)
  - 모니터/알람(Discord/Slack), Metric (Prometheus) + 대시보드(Grafana/Streamlit)
  - CD: Docker 이미지 + GitHub Actions(테스트→스테이징→카나리→프로덕션)

성공 기준 (MVP)
- 샌드박스 계좌에 안전하게 주문을 전송하고(또는 dry-run으로 시뮬레이션), 재시작 후 주문 상태를 재동기화할 수 있다.
- 위험관리 규칙(포지션 사이징, 일일 최대 손실)이 주문 전 적용된다.
- 주요 실패 시 자동 롤백/알람이 동작하고, 감사 로그로 누가 무엇을 승인했는지 확인 가능하다.

테스트 포인트
- 유닛: 위험관리 로직(경계값, 제약), 주문 idempotency, 시뮬레이터
- 통합: 샌드박스 브로커와의 엔드투엔드 플로우(dry-run+approve+commit)
- 부하: 실시간 주문 스트림에서 10~100 TPS 시뮬레이션

보안/규정 고려사항
- API 키/시크릿은 절대 로그에 남기지 말고 keyring/Vault로 관리
- 승인/운영상 변경은 감사 로그에 남기고 무결성(체크섬) 보장
- 실거래 전 사전 체크리스트(자금 여력, 마켓상태, 트레이드 서킷 브레이커 등)
