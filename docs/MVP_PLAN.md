# 초기 구현 계획 (MVP)

이 문서는 주식 자동매매 프로젝트의 최소 실행 가능 제품(MVP)을 정의하고, 초기 아키텍처와 데이터 흐름을 설계합니다.

## 1. MVP (최소 실행 가능 제품) 정의

- **목표**: 매일 아침, AI 모델이 추천하는 상위 5개 종목을 선정하여 사용자에게 보고하고, 사용자의 승인을 받아 지정된 예산 내에서 균등하게 매수 주문을 실행한다.
- **핵심 기능 (In-Scope)**:
  1. **데이터 수집**: 특정 종목 목록에 대한 일봉 시세(OHLCV) 데이터 수집.
  2. **AI 분석**: 간단한 시계열 예측 모델(예: RandomForest 또는 LSTM)을 사용하여 다음 날 주가 등락을 예측하고, 신뢰도 점수 산출.
  3. **종목 선정**: 예측 점수와 기본 필터(최소 거래대금)를 결합하여 상위 5개 종목 선정.
  4. **주문 실행**: 증권사 API를 통해 선정된 종목에 대한 시장가 매수 주문 실행 (사용자 승인 후).
  5. **보고**: 매일 아침 추천 종목과 간단한 근거를 텍스트 파일 또는 텔레그램으로 보고.
- **범위 제외 (Out-of-Scope)**:
  - 실시간 매도 로직 (익절/손절). MVP에서는 매수만 다룸.
  - 복잡한 UI. 모든 상호작용은 CLI, 텔레그램 봇, 또는 간단한 스크립트 실행으로 처리.
  - 포트폴리오 최적화.

## 2. 아키텍처 설계 (초안)

- **구성 요소**:
  - **Scheduler (Windows 작업 스케줄러 / cron)**: 매일 정해진 시간에 전체 프로세스를 실행.
  - **Data Collector**: `src/data/` 모듈. `FinanceDataReader` 등을 이용해 시세 데이터를 수집하고 CSV 또는 SQLite에 저장.
  - **AI Analyzer**: `src/models/` 모듈. 저장된 데이터를 읽어 전처리하고, 학습된 모델로 예측을 수행.
  - **Order Manager**: `src/trading/` 모듈. 증권사 API와 통신하여 주문을 생성하고 실행.
  - **Notifier**: `src/ui/` 모듈. 사용자에게 텔레그램 또는 이메일로 결과를 보고.
  - **Main Controller**: `main.py`. 각 모듈을 순서대로 호출하고 전체 워크플로우를 제어.

- **아키텍처 다이어그램 (텍스트)**:
  ```
  [Scheduler] -> [main.py]
                   |
                   +--> [Data Collector] -> [Data Store (CSV/DB)]
                   |
                   +--> [AI Analyzer] --(reads)--> [Data Store]
                   |      |
                   |      +-- (predicts) --> [Top 5 Tickers]
                   |
                   +--> [Notifier] --(sends)--> [User (Telegram)]
                   |      |
                   |      +-- (receives approval)
                   |
                   +--> [Order Manager] --(executes)--> [Brokerage API]
  ```

## 3. 데이터 흐름

1. **(06:00 AM)** `Scheduler`가 `main.py` 실행.
2. `Data Collector`가 전일 시세 데이터를 업데이트.
3. `AI Analyzer`가 업데이트된 데이터를 로드하여 전처리 및 예측 수행.
4. 예측 결과 상위 5개 종목과 근거 데이터를 `reports/YYYY-MM-DD.txt` 파일로 저장.
5. `Notifier`가 보고서 내용을 사용자에게 텔레그램 메시지로 발송.
6. 사용자가 텔레그램 봇에 '매수' 명령을 보내면, `Notifier`가 `main.py`에 신호를 전달.
7. `Order Manager`가 계좌 잔고를 확인하고, 5개 종목에 대해 균등 분할하여 시장가 매수 주문 전송.
8. 주문 체결 결과를 로그에 기록하고, 사용자에게 최종 알림.

## 4. 인증 및 보안

- **API 키 관리**: 모든 API 키, 시크릿, 텔레그램 토큰은 환경변수를 통해 주입. `.env` 파일을 로컬 개발에 사용하고, `.gitignore`에 추가하여 유출 방지.
- **로깅**: 로그 파일에 민감한 개인정보나 API 키가 기록되지 않도록 필터링.
- **접근 제어**: 서버에서 실행될 경우, 해당 서버에 대한 접근 권한을 최소화.
