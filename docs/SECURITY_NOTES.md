# 보안 및 시크릿 관리 주의사항

이 문서는 실전 적용 시 개발자와 운영자가 반드시 지켜야 할 기본 보안 수칙을 정리합니다.

1) 시크릿(API 키, 비밀번호 등) 관리
  - 절대 소스 코드에 하드코딩하지 마십시오.
  - 로컬 개발 시에는 `keyring`을 사용해 OS 키체인에 저장하세요 (`scripts/operator_set_creds.py` 제공).
  - CI/CD에서는 GitHub Secrets를 사용하고, 워크플로우에서만 참조하세요.

2) 로그 마스킹
  - 예외 메시지나 로그에 API 키/토큰/계좌번호가 노출되지 않도록 마스킹 처리합니다.
  - `ApprovalManager`와 감사 로그에는 민감값을 마스킹하는 로직이 포함되어 있습니다.

3) CI 아티팩트
  - 테스트/빌드 아티팩트 업로드 시 민감정보(예: 환경변수, 토큰, 풀 로그 등)가 포함되지 않도록 주의하세요.
  - 필요 시 로그 필터링 스크립트를 도입해 민감정보를 탐지/제거하세요.

4) 레지스트리 푸시
  - 워크플로우는 레지스트리 푸시를 secrets(DOCKER_REGISTRY, DOCKER_USERNAME, DOCKER_PASSWORD) 기준으로 수행합니다.
  - 권한이 최소한인 서비스 계정을 사용하고, 토큰의 만료/회전 정책을 마련하세요.

5) 운영 권한
  - 운영자 계정은 최소권한 원칙을 따르며, 감사 로그에 모든 승인/거부/수동 조작을 남기세요.
