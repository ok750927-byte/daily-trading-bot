# 운영 런북 (초안)

목표: 운영자가 장애/이벤트를 빠르게 파악하고, 안전하게 시스템을 복구할 수 있도록 단계별 플레이북을 제공합니다.

1) 모니터링 및 알람
  - 필수 메트릭: 주문 실패율, 미체결 주문 수, API 에러율, 지연(latency) P95/P99, 계좌 잔액/증감
  - 알람 채널: Slack/Discord/Email (중요) — 짧은 메시지 + 링크(GitHub Actions, Grafana, Logs)

2) 사고 분류
  - 계좌/자금 이슈: 잔액 부족, 계좌 인증 실패
  - 브로커 API 이슈: 응답 없음, 인증 거부, 레이턴시 급증
  - 트레이드 로직 이슈: 위험규칙 위반, 데이터 이상치

3) 긴급 중지 절차
  - 운영자가 수동으로 모든 실시간 Trader를 일시정지
  - 브로커 주문 전송 차단 플래그 설정 (feature flag)
  - 통지: 팀 채널에 사고 알림, 주요 로그 첨부

4) 복구 절차
 1. 원인 규명: 최근 로그(Orders, Approval Audit, Broker adapter logs) 확인
 2. 미체결 주문 검증: OrderManager와 브로커 상태 동기화, 필요시 취소 또는 재발주
 3. 시스템 재시작: 필요한 서비스(모니터, trader)를 순서대로 재기동
 4. 검증: 샌드박스 또는 소량(0.1~1%) 자금으로 smoke test

5) 롤백
  - 배포에 문제가 있는 경우: 즉시 이전 안전 버전으로 롤백하고 카나리 트래픽을 줄임

6) 사후 조치
  - RCA(원인·영향 분석), 개선 계획, 테스트 케이스 추가

부록: 체크리스트
 - 운영자 연락처
 - 브로커 API status 페이지 URL
 - GitHub Actions workflow URL (CI)
